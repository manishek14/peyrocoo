# Peyrocoo — سامانه ثبت و پیگیری درخواست کارکنان

این ریپو شامل سورس‌کد کامل یک اپلیکیشن وب دو بخشی بر پایه **Laravel 8** است:

- **پنل کارکنان** (بخش عمومی سایت): کارکنان ثبت‌نام و ورود می‌کنند، درخواست خود را همراه با تصویر ثبت می‌کنند و پاسخ مدیر را همان‌جا مشاهده می‌کنند. همچنین یک صفحه «راهنما» دارد.
- **پنل مدیریت**: مدیران وارد پنل می‌شوند، درخواست‌های ثبت‌شده را می‌بینند و برای هر درخواست پاسخ ثبت می‌کنند؛ به‌همراه مدیریت ادمین‌ها و کاربران.

> نام دامنه اصلی پروژه `peyrocoo.ir` بود و این سورس از بکاپ واقعی سرور (cPanel) استخراج و مرتب‌سازی شده است.

## ساختار پروژه

مطابق چیدمان سرور اصلی (cPanel)، دو بخش کنار هم قرار می‌گیرند:

```
peyrocoo/                  ← ریشه ریپو = محتوای public_html (وب‌روت)
├── index.php              ← نقطه ورود سایت؛ اپلیکیشن Laravel را از ../panel بوت می‌کند
├── .htaccess              ← همه درخواست‌ها را به index.php هدایت می‌کند
├── admin-assets/          ← فایل‌های استاتیک قالب پنل (Metronic) و پلاگین‌ها
├── uploads/               ← فایل‌های آپلودی زمان اجرا (عکس درخواست‌ها و ...) در سرور ساخته می‌شود
└── panel/                 ← اپلیکیشن کامل Laravel 8.83
    ├── app/               ← مدل‌ها، کنترلرها، میدل‌ورها، هِلپرها و Presenter ها
    ├── routes/            ← روت‌ها در دو گروه: app/ (کارکنان) و admin/ (مدیریت)
    ├── resources/views/   ← قالب‌های Blade دو پنل
    ├── database/          ← مایگریشن‌ها و Seeder
    └── config, tests, ...
```

**نکته معماری:** فایل `public_html/index.php` با مسیر نسبی `../panel/...` به اپلیکیشن وصل می‌شود؛ پس موقع دیپلوی باید پوشه `panel` هم‌سطح (کنار) وب‌روت باشد، نه داخل آن.

## جریان کار اپلیکیشن

| بخش | مسیر | توضیح |
|---|---|---|
| کاربر | `/register` و `/login` | ثبت‌نام و ورود با شماره موبایل + رمز عبور |
| کاربر | `/` | داشبورد کاربر (نیاز به ورود) |
| کاربر | `/create-applying` | ثبت درخواست جدید (عنوان + تصویر) |
| کاربر | `/applying-for` | فهرست درخواست‌ها و پاسخ‌های دریافتی |
| کاربر | `/rahnama` | صفحه راهنما |
| ادمین | `/auth/admin/login` | ورود مدیر |
| ادمین | `/admin/dashboard` | داشبورد مدیریت |
| ادمین | `/admin/applying-for` | مشاهده درخواست‌ها و ثبت پاسخ |
| ادمین | `/admin/users` ، `/admin/admins` | مدیریت کاربران و ادمین‌ها |

جداول اصلی دیتابیس: `users`، `admins`، `applying_fors` (شامل فیلد پاسخِ مدیر: `javab`).

## پیش‌نیازها

- **PHP** نسخه `^7.3|^8.0` (روی سرور اصلی با PHP 8.1 اجرا می‌شد؛ با 8.2 هم تست شده) به‌همراه اکستنشن‌های استاندارد Laravel: `mbstring`، `openssl`، `pdo_mysql` (یا `pdo_sqlite`)، `gd`، `fileinfo`، `curl`، `zip`
- **Composer 2**
- **MySQL** (پیش‌فرض پروژه) — برای تست محلی می‌توان از SQLite استفاده کرد

## راه‌اندازی گام‌به‌گام

### ۱) دریافت کد

```bash
git clone https://github.com/manishek14/peyrocoo.git
cd peyrocoo
```

### ۲) نصب وابستگی‌ها

```bash
cd panel
composer install
```

### ۳) تنظیم فایل محیط

فایل `.env` در ریپو قرار ندارد (شامل رمزهای واقعی سرور است و نباید باشد). از نمونه یک کپی بسازید و مقدارها را تنظیم کنید:

```bash
cp .env.example .env
php artisan key:generate
```

برای تست محلی با SQLite، این خطوط را در `.env` بگذارید و فایل دیتابیس را بسازید:

```env
DB_CONNECTION=sqlite
```

```bash
touch database/database.sqlite
```

برای محیط واقعی، مقادیر MySQL (هاست، نام دیتابیس، کاربر و رمز) را تنظیم کنید — مطابق `.env.example` نام دیتابیس روی سرور اصلی `kiantash` بود.

### ۴) ساخت جداول و داده اولیه

```bash
php artisan migrate --seed
```

Seeder یک ادمین پیش‌فرض می‌سازد:

| نام کاربری | رمز عبور |
|---|---|
| `admin` | `password` |

⚠️ بعد از راه‌اندازی روی سرور واقعی، همین اول رمز ادمین را عوض کنید.

### ۵) لینک فایل‌های آپلودی

```bash
php artisan storage:link
```

### ۶) اجرا

**روش توسعه (بدون وب‌سرور):** از ریشه ریپو، با فایل `router.php` که نقش `.htaccess` را برای سرور داخلی PHP بازی می‌کند:

```bash
# از ریشه ریپو (کنار index.php):
php -S 127.0.0.1:8080 router.php
```

سپس `http://127.0.0.1:8080/login` را باز کنید. (اگر از SQLite استفاده می‌کنید، مطمئن شوید `APP_URL=http://localhost:8080` در `.env` تنظیم شده است.)

**روش production:** وب‌سرور (Apache/Nginx) با docroot روی پوشه `public_html` و پوشه `panel` هم‌سطح آن، دقیقاً مثل سرور اصلی. محتوای `.htaccess` موجود، درخواست‌های غیرفایلی را به `index.php` می‌رساند.

## اجرا با Docker (سریع‌ترین راه)

فایل‌های داکر آماده است؛ یک سرویس وب (PHP 8.1 + Apache) و یک سرویس MySQL با healthcheck:

```bash
docker compose up -d --build
```

بعد از بالا آمدن کانتینرها:

- سایت کارکنان: `http://localhost:8080/login` (ثبت‌نام از `/register`)
- پنل مدیریت: `http://localhost:8080/auth/admin/login` — ادمین پیش‌فرض `admin` / `password` (فقط بار اول توسط seeder ساخته می‌شود)

نقش هر فایل:

| فایل | نقش |
|---|---|
| `Dockerfile` | دو مرحله‌ای: نصب وابستگی‌ها با Composer + ایمیج `php:8.1-apache` با docroot روی `public_html` و `panel` کنار آن (مطابق چیدمان سرور اصلی) |
| `docker-compose.yml` | سرویس‌های `web` و `db` (MySQL 8)؛ دیتابیس در volume `db_data` و فایل‌های آپلودی در volume `uploads` ماندگارند |
| `docker/entrypoint.sh` | ساخت `.env` از قالب، تولید `APP_KEY`، انتظار برای دیتابیس، `migrate` و seeder فقط بار اول، تنظیم دسترسی‌ها، سپس اجرای Apache |
| `docker/env.docker` | قالب تنظیمات محیط کانتینر (`DB_HOST=db` و ...) |
| `docker/apache.conf` | تنظیمات Apache با `AllowOverride All` برای `.htaccess` |

**برای production:** پسورد دیتابیس را در `docker-compose.yml` و `docker/env.docker` عوض کنید، `APP_URL` را با دامنه خودتان جایگزین کنید و `APP_DEBUG=false` نگه دارید. ایمیل‌ها روی حالت `log` هستند (در لاگ Laravel نوشته می‌شوند)؛ برای ارسال واقعی، تنظیمات SMTP را در `.env` کانتینر قرار دهید.

## نکات مهم

- فایل‌های آپلودی کاربران در `uploads/` وب‌روت نوشته می‌شوند (نه داخل `panel/public`)؛ پس وب‌روت باید قابل‌نوشتن باشد.
- فایل `.env` هرگز به ریپو push نمی‌شود؛ کلیدها و رمزها فقط روی سرور.
- لاگ‌ها در `panel/storage/logs/laravel.log` نوشته می‌شوند.
- در بررسی اولیه، دو مشکل سورس برطرف شد: یک `dd()` جا‌مانده در کد ورود ادمین حذف و view صفحه‌بندی `vendor.pagination.bootstrap-4` که به آن ارجاع شده بود اضافه شد (commit `f1e3653`).
